# 알약몬 MVP 단계별 계획

2026-11-05 MVP 기획서를 개발 단계로 나눈 문서입니다. [DESIGN.md](DESIGN.md) 9장의 확장(캐릭터 성장과 몬스터 퇴치)을 MVP 범위로 좁히고, 어떤 순서로 만들지 정합니다. 기획서와 설계 문서의 용어가 다르면 이 문서를 따릅니다(질병 몬스터 → 처방 몬스터, 치료약 → 처방약).

## 1. 목표와 범위

알약몬은 약이나 영양제를 먹기 전에 한 장 찍으면 기록이 남고, 그 기록으로 내 캐릭터가 자라고 처방 몬스터를 물리치는 10~20대용 복용 기록 앱입니다.

**차별점: 사진으로 확인한 기록만 보상에 반영합니다.** 체크 버튼 앱은 누르기만 하면 보상을 받아 쉽게 속일 수 있습니다. 알약몬은 일정에 있는 약이 사진에서 확인되어야 캐릭터가 자라고 몬스터 체력이 줄어듭니다.

MVP의 목표는 하나입니다. **10~20대가 4주 동안 매일 기록을 이어 가는지** 확인합니다.

### 1.1 타깃 사용자

**만 14~29세**입니다. 만 14세 미만은 개인정보를 처리할 때 법정대리인 동의가 필요해 MVP에서 뺍니다.

| 사용자 | 상황 | 문제 | 알약몬에서 쓰는 기능 |
|---|---|---|---|
| 22세 대학생 | 비타민 D, 유산균, 오메가3를 샀지만 일주일을 넘기기 어려움 | 먹어도 변화가 없어 잊음 | 캐릭터 성장, 꾸미기 |
| 17세 고등학생 | 피부과에서 여드름약 4주 처방 | 피부가 조금 좋아지면 끊음 | 처방 몬스터 퇴치 |
| 25세 직장인 | 천식으로 매달 같은 약을 처방받음 | 매일 똑같아 따분함 | 처방이 나올 때마다 새 몬스터 |

10~20대가 약을 꾸준히 못 먹는 이유는 잊어서가 아니라 **계속 먹을 이유가 없어서**입니다. 기존 복약 앱은 중장년을 대상으로 알림과 체크 버튼만 제공합니다.

### 1.2 MVP에서 하는 것과 하지 않는 것

MVP는 지금 앱(사진 기록, 기기 안 탐지, 로그인 없음) 위에 **처방 몬스터와 캐릭터 성장**만 올립니다. 서버가 필요한 기능은 모두 뒤로 미룹니다.

| 기능 | MVP에서 하는 것 | 단계 |
|---|---|---|
| 사진 복용 기록 | 지금 그대로 유지 | - |
| 약 종류 구분 | 영양제, 처방약, 필요할 때 먹는 약 | 1 |
| 처방 등록 | 직접 입력 (약, 시작일, 일수, 하루 횟수, 1회 알 수) | 1 |
| 처방 몬스터 | 처방 하나에 몬스터 하나. 다 먹으면 퇴치, 새 처방이 들어오면 새 몬스터 | 2 |
| 보상 규칙 | 사진 확인, 하루 기준량, 회차 시간 범위 | 2 |
| 캐릭터 성장 | 영양제 일정을 지킨 날수만큼 5단계 성장 | 3 |
| 뽑기와 컬렉션 | 무료 뽑기, 스킨·액세서리 12종, 몬스터 펫, 기기 안 컬렉션 | 4 |
| 공유 카드 | 내 캐릭터를 이미지로 저장해 SNS에 올림. 약 이름과 병명은 안 나옴 | 5 |

**MVP에서 하지 않는 것**

- 처방전·약봉투 OCR: 웹 출시가 먼저인데 브라우저에서 기기 안 한글 OCR 품질을 아직 확인하지 못함. 직접 입력으로 먼저 흐름을 검증 (DESIGN.md 9.1)
- 복용 알림
- 친구, 공개 프로필, 다른 사람 캐릭터 보기 (계정과 서버 필요)
- 영양제 제품 정보 자동 입력
- 유료 상품, 시즌 이벤트

## 2. 단계 한눈에 보기

| 단계 | 내용 | 기획서 개발 순서 | 끝난 기준 |
|---|---|---|---|
| 1 | 약 종류와 처방 등록 | 1, 2 | 약에 종류를 붙이고, 처방을 등록하면 회차별로 홈의 오늘 일정에 나옴 |
| 2 | 몬스터 체력과 보상 규칙 | 3, 4 | 사진 기록으로만 체력·경험치가 바뀌고, 하루 상한과 재계산이 테스트로 검증됨 |
| 3 | 캐릭터 성장과 홈 화면 | 5 | 홈이 캐릭터·몬스터 무대가 되고, 저장하면 체력 감소와 경험치가 바로 보임 |
| 4 | 뽑기, 컬렉션, 장착 | 6 | 뽑기권을 써서 얻은 스킨·액세서리·펫을 캐릭터에 장착하고 컬렉션에서 봄 |
| 5 | 연출과 공유 카드 | 7 | 보상·퇴치·뽑기 연출이 나오고, 캐릭터 이미지를 저장할 수 있음 |
| 6 | 테스트 배포와 4주 검증 | - | 테스터 10명이 4주 동안 쓰고 지표를 냄 |

- **보상 규칙(2단계)을 연출(5단계)보다 먼저 만듭니다.** 규칙이 틀리면 연출을 다시 만들어야 하기 때문입니다.
- 단계마다 `main`에 합쳐 웹에 배포하고(DESIGN.md 6장), 그 단계의 끝난 기준을 웹에서 확인합니다.
- 테이블을 더하는 단계는 그 단계 안에서 엑셀 백업(DESIGN.md 5.2)에도 넣습니다. 나중에 한꺼번에 하지 않습니다.

```text
1 약 종류·처방 ──▶ 2 몬스터·보상 규칙 ──▶ 3 캐릭터·홈 ──▶ 4 뽑기·컬렉션 ──▶ 5 연출·공유 카드 ──▶ 6 4주 검증
   (데이터)          (계산, 화면 최소)       (무대)           (보상 소비)        (보여 주기)
```

## 3. 모든 단계에 걸친 원칙

게임 요소가 약을 잘못 먹게 만들거나 병을 드러내면 안 됩니다. 단계마다 아래를 지키는지 확인합니다.

- **병명과 약 이름은 드러내지 않습니다.** 몬스터, 펫, 컬렉션, 공유 카드 어디에도 나오지 않습니다. 건강 정보는 개인정보보호법상 민감정보입니다.
- **사진과 기록은 기기 안에 둡니다.** 지금 원칙을 그대로 지킵니다.
- **보상은 더 먹게 만들지 않습니다.** 하루 기준량, 회차 시간 범위, 필요할 때 먹는 약 제외, 제품 수와 무관한 보상.
- **의료 조언을 하지 않습니다.** 놓친 약은 "의사·약사의 안내를 따르세요"로 안내합니다.
- **만 14세 이상만 씁니다.** 처음 열 때 나이를 확인합니다 (6단계).
- **뽑기는 무료이고 확률을 공개합니다.** 청소년 사용자가 있어 판매는 하지 않습니다.
- **모델의 한계를 알립니다.** 의약품 96종만 알아보고 영양제는 모른다는 점을 앱 안에 적습니다.

## 4. 1단계: 약 종류와 처방 등록

보상이 올라갈 데이터 바탕을 만듭니다. 게임 요소는 아직 없습니다.

### 4.1 약 종류

약을 등록할 때 세 가지 중 하나를 고릅니다. 종류가 보상 방식을 정합니다.

| 종류 | 예 | 하루 기준량 | 게임 연결 (뒤 단계) |
|---|---|---|---|
| 영양제 | 비타민 D, 유산균 | 제품에 적힌 하루 권장량 (사용자가 입력) | 캐릭터 성장 |
| 처방약 | 항생제, 여드름약, 천식약 | 하루 횟수 × 1회 알 수 (처방에서) | 처방 몬스터 |
| 필요할 때 먹는 약 | 진통제, 생리통약 | 없음 | 없음. 기록만 남김 |

- 탐지 모델은 의약품 96종만 알고 **영양제는 모릅니다.** 영양제는 처음에 "알 수 없는 물체"로 나오고, 사용자가 한 번 고르면 다음부터 색·모양으로 추천합니다(DESIGN.md 3.6). 이 흐름은 이미 있으므로 그대로 씁니다.
- 결과 확인에서 처음 기록하는 약을 등록할 때도 종류를 고릅니다.

### 4.2 처방 등록 (직접 입력)

처방 하나는 병원에서 한 번에 받은 약들의 묶음입니다.

| 항목 | 예 | 비고 |
|---|---|---|
| 약 (여러 개) | 여드름약 A, 위장약 B | 96종 검색, 식약처 검색, 직접 입력 (지금 약 고르기와 같음). 고른 약은 처방약이 됨 |
| 시작일 | 11월 5일 | 기본값 오늘 |
| 처방 일수 | 28일 | 2단계에서 몬스터 체력이 됨 |
| 하루 복용 횟수와 시간 | 2회 (아침, 저녁) | 회차마다 시간 |
| 1회 알 수 | 약마다 1알 | 하루 기준량을 정함 |

처방 속 약의 회차 시간이 홈의 오늘 일정과 결과 확인의 **예정과 비교**(DESIGN.md 4장)에 들어갑니다. 처방 기간이 지나면 그 회차는 일정에서 빠집니다.

### 4.3 데이터

| 테이블 | 주요 칸 | 용도 |
|---|---|---|
| `medications` (기존) | + `kind` (영양제/처방약/필요할 때), `daily_limit` | 종류와 하루 기준량 |
| `prescriptions` | 시작일, 일수, 상태(진행/퇴치/끝냄) | 처방 묶음 |
| `prescription_items` | 처방, 약, 하루 횟수, 회차 시간, 1회 알 수 | 처방 속 약 |

엑셀 백업의 `약` 시트에 종류와 하루 기준량을, 새 `처방` 시트에 처방과 처방 속 약을 넣습니다.

### 4.4 화면

| 화면 | 바뀌는 것 |
|---|---|
| 약 관리 | 약 추가·수정에서 종류를 고름. 영양제는 하루 권장량 입력 |
| 처방 등록 (새로) | 약, 시작일, 일수, 횟수와 시간, 알 수. 약 관리에서 들어감 |
| 홈(오늘) | 처방 회차가 오늘 일정에 보임 |

### 4.5 끝난 기준

- 약 세 종류를 고르고 저장할 수 있고, 기존 약도 종류를 고칠 수 있음
- 28일 처방을 등록하면 홈의 오늘 일정에 회차별로 나오고, 결과 확인의 예정과 비교에도 들어감
- 엑셀로 내보내고 가져왔을 때 종류·하루 기준량·처방이 그대로 돌아옴

## 5. 2단계: 몬스터 체력과 보상 규칙

보상 **계산**을 만듭니다. 화면은 숫자와 표로 최소만 두고, 규칙을 테스트로 검증합니다.

### 5.1 처방 몬스터

**처방 하나가 몬스터 하나입니다.** 단기 처방과 만성질환 처방을 같은 규칙으로 다룹니다.

| 규칙 | 내용 |
|---|---|
| 등장 | 처방을 등록하면 바로 등장. 처방이 여러 개면 몬스터도 여러 마리 |
| 체력 | 처방 일수와 같음 (28일 처방 = 체력 28) |
| 공격 | 그날 회차를 **모두** 사진으로 기록하면 체력 1 감소. 하루 최대 1 |
| 놓친 날 | 체력이 줄지 않을 뿐 벌은 없음. 몬스터는 그대로 남음 |
| 퇴치 | 체력 0. 뽑기권 1장 + 그 몬스터의 펫 + 캐릭터 경험치 3 (연출은 5단계, 펫·뽑기권은 4단계) |
| 새 처방 (만성질환) | 약이 떨어지기 전에 다시 처방받아도 새 처방으로 보고 새 몬스터 등장. 이전 몬스터는 따로 남아 자기 처방을 다 먹으면 퇴치. 두 처방에 같은 약이 있으면 하루 기준량은 하나만 적용하고, 그날 기록은 먼저 등록한 처방의 몬스터부터 깎음 (처방이 겹쳐도 약을 두 배로 먹지 않게) |
| 처방 끝내기 | 의사가 약을 중단하면 사용자가 "처방 끝내기"를 누름. 몬스터는 물러나고, 깎은 체력만큼 캐릭터 경험치를 받음. 펫은 없음 |
| 외형과 이름 | **병명을 쓰지 않음.** 처방 속 약의 색과 모양으로 만듦 (예: 주황 캡슐 → 주황 캡슐 몬스터). 그림은 3단계, 이 단계는 이름만 |

```text
처방 등록 ──▶ 몬스터 등장 (체력 = 일수)
                 │ 그날 회차를 모두 사진으로 기록 → 체력 -1 (하루 최대 1)
                 │ 놓친 날 → 그대로
                 ├─▶ 체력 0 → 퇴치: 펫 + 뽑기권 1 + 경험치 3
                 └─▶ 처방 끝내기 → 물러남: 깎은 체력만큼 경험치, 펫 없음
```

놓친 약을 어떻게 할지는 앱이 정하지 않습니다. "의사·약사의 안내를 따르세요"라고 안내하고, 몬스터는 기록한 날만큼만 줄어듭니다.

### 5.2 보상 규칙

보상은 **약을 더 먹게 만들지 않는 범위에서만** 줍니다.

| 규칙 | 내용 |
|---|---|
| 사진 확인 | 사진에서 찾은 약(모델이 찾거나 사용자가 고른 물체)이 일정과 맞아야 보상. 사진 없이 직접 기록하면 기록은 되지만 보상은 없음 (`intake_records.source`가 camera인 기록만) |
| 하루 기준량 | 처방약은 하루 횟수 × 1회 알 수, 영양제는 하루 권장량까지만 반영. 넘는 기록에는 보상 없음 |
| 회차 시간 범위 | 회차 시간 앞뒤 3시간 안의 기록만 인정 (제안, 8장). 아침 약을 저녁에 몰아 먹어도 보상 없음 |
| 필요할 때 먹는 약 | 보상 없음 |
| 제품 수 | 보상은 "오늘 일정을 다 지켰는가" 하나로 줌. 영양제를 늘려도 보상은 늘지 않음 |

같은 알약을 매번 찍기만 하는 것까지 막지는 못합니다. 다만 하루 보상에 상한이 있어서 속여도 얻는 것이 작습니다.

### 5.3 경험치 계산

캐릭터 단계와 화면은 3단계에서 만들지만, 경험치 수치는 이 단계에서 계산해 둡니다.

| 경험치 | 조건 |
|---|---|
| 1 | 영양제 일정을 모두 지킨 날. 영양제를 몇 개 먹든 하루 1 |
| 3 | 처방 몬스터 퇴치. 처방약만 먹는 사용자도 캐릭터를 키울 수 있게 |
| 깎은 체력만큼 | 처방 끝내기 |

빠뜨린 날에도 경험치는 줄지 않습니다. 연속 기록만 끊깁니다.

### 5.4 다시 계산

보상은 복용 기록에서 다시 계산할 수 있게 둡니다. 날마다 하루 기준량까지 자른 사진 기록으로 그날의 몬스터 공격과 경험치를 정하므로, 기록을 고치거나 지우거나 백업에서 가져와도 같은 결과가 나옵니다. 기록을 고치거나 지우면 그날 보상도 다시 계산합니다.

### 5.5 데이터

| 테이블 | 주요 칸 | 용도 |
|---|---|---|
| `monsters` | 처방, 색·모양 | 몬스터 이름. 처음 알게 된 생김새로 정하고 바꾸지 않음 |
| `prescriptions` (1단계) | + 끝낸 날 | 처방 끝내기. 끝낸 날까지 깎은 체력으로 경험치 |

**체력·경험치·하루 보상은 저장하지 않고 기록에서 매번 다시 셉니다** (`lib/utils/reward_calculator.dart`). 처음 계획한 `daily_rewards`와 `monsters`의 체력·퇴치일 칸은 두지 않습니다. 저장한 값을 쌓지 않으므로 같은 날 두 번 지급할 수 없고, 기록을 고치거나 지우거나 백업에서 가져와도(5.4) 같은 결과가 나옵니다. 기록은 하루 몇 개뿐이라 매번 세어도 빠릅니다. 백업에는 처방 시트에 끝낸 날만 더합니다.

계산 순서 (날마다):

1. 사진 기록(camera)만, 영양제·처방약만 씁니다. 종류를 고르지 않은 약도 보상이 없습니다.
2. 기록을 회차 시간 앞뒤 3시간 안의 가장 가까운 빈 회차에 한 알씩 채웁니다. 회차마다 그 회차 개수까지, 약마다 하루 기준량까지만 채웁니다.
3. 영양제 회차(약에 정한 복용 시간)가 모두 차면 경험치 1. 복용 시간이 없는 영양제는 일정이 아니므로 세지 않습니다.
4. 채운 처방 회차를 먼저 등록한 처방부터 나눠 주고, 그날 회차가 모두 찬 처방의 몬스터 체력 -1.

### 5.6 화면

| 화면 | 바뀌는 것 |
|---|---|
| 홈(오늘) | 진행 중인 몬스터 이름과 남은 체력을 숫자로. 오늘 경험치 받았는지 |
| 몬스터 상세 (새로) | 남은 체력, 지난 기록(날짜별로 깎았는지), 처방 끝내기. 표와 숫자로 |
| 결과 확인 → 저장 | 저장 뒤 "몬스터 체력 -1", "경험치 +1" 같은 글로 알림. 연출은 5단계 |

### 5.7 끝난 기준

- 아래가 단위 테스트로 검증됨
  - 사진 없는 기록(manual)은 체력·경험치를 바꾸지 않음
  - 회차를 하나라도 놓친 날은 체력이 줄지 않음. 회차 시간 범위 밖의 기록은 인정하지 않음
  - 하루 기준량을 넘는 기록은 보상에 들어가지 않음. 같은 날 두 번 지급되지 않음
  - 같은 약이 든 처방 둘이 겹치면 먼저 등록한 처방의 몬스터부터 깎임
  - 기록을 지우면 그날 보상이 사라지고, 백업에서 가져와도 결과가 같음
- 28일 처방을 등록하고 테스트 데이터로 28일을 채우면 체력 0이 되고 퇴치 상태가 됨

## 6. 3단계: 캐릭터 성장과 홈 화면

홈 화면을 캐릭터와 몬스터가 있는 무대로 바꿉니다.

### 6.1 캐릭터 성장

아이콘의 라임색 캐릭터(`assets/icon/app_icon.png`)가 기본 캐릭터입니다. 누적 경험치로 5단계 성장합니다.

| 단계 | 필요한 누적 경험치 |
|---|---|
| 알 | 0 |
| 아기 | 3 |
| 어린이 | 7 |
| 성장 | 14 |
| 완성 | 30 |

### 6.2 몬스터 외형

병명을 쓰지 않고 처방 속 약의 색과 모양으로 만듭니다. MVP는 **기본 몬스터 6종**에 약 색을 입힙니다. 약의 색·모양은 `appearances`(DESIGN.md 3.6)와 식약처 생김새(DESIGN.md 5.4)에서 가져오고, 없으면 기본 몬스터를 씁니다.

### 6.3 데이터

| 테이블 | 주요 칸 | 용도 |
|---|---|---|
| `character` | 장착한 스킨·액세서리·펫 | 내 캐릭터의 장착 (4단계에 만듦) |

경험치와 단계는 저장하지 않습니다. 경험치는 기록에서 다시 세고(5.5), 단계는 경험치로 정합니다(`lib/utils/character.dart`). 그래서 3단계에는 새 테이블이 없고, `character`는 장착을 넣는 4단계에 만듭니다.

**그림**: 캐릭터 5단계와 기본 몬스터 6종(동글, 캡슐, 가시, 유령, 젤리, 뿔)은 아이콘 캐릭터 화풍으로 코드로 그립니다(`lib/ui/common/creature_art.dart`). 몬스터 몸 색은 약의 색 이름에서, 캡슐·길쭉한 약은 캡슐 몬스터로, 나머지는 처방마다 정해진 하나로 고릅니다. 디자인한 그림이 나오면 이 파일만 바꿉니다.

### 6.4 화면

| 화면 | 보여 주는 것 |
|---|---|
| 홈 | 내 캐릭터(단계별 그림), 진행 중인 몬스터와 체력 막대, 오늘 일정, 기록하기 버튼(지금처럼 가장 큰 버튼). 더 보기 메뉴는 그대로 |
| 보상 결과 | 저장 직후 몬스터 체력 감소와 경험치 막대 변화를 보여 주는 화면. 애니메이션은 5단계 |
| 몬스터 상세 | 2단계 화면에 몬스터 그림을 더함 |

**하루 흐름**

1. 홈에서 오늘 일정과 몬스터를 봄
2. 기록하기 → 사진 찍기
3. 찾은 약을 확인·수정하고 저장
4. 그날 마지막 회차면 몬스터 체력 감소, 영양제 일정을 다 지켰으면 경험치
5. 홈으로 돌아감

### 6.5 끝난 기준

- 홈에서 캐릭터 단계와 몬스터 체력이 그림으로 보이고, 저장 뒤 홈에 돌아오면 값이 바뀌어 있음
- 경험치 3·7·14·30에서 캐릭터 그림이 바뀜
- 처방 둘을 등록하면 몬스터 둘이 각자 체력으로 보임

## 7. 4단계: 뽑기, 컬렉션, 장착

모은 보상을 쓰고 보여 주는 곳을 만듭니다.

### 7.1 규칙

| 항목 | 내용 |
|---|---|
| 뽑기권 얻기 | 일정을 7일 연속으로 지키면 1장(`daily_rewards`에서 셈), 몬스터를 퇴치하면 1장 |
| 뽑기 풀 | 스킨·액세서리 12종. 일반 70%, 희귀 25%, 유니크 5% (확률은 화면에 공개) |
| 몬스터 펫 | 퇴치한 몬스터가 작은 펫이 됨. 뽑기로는 얻을 수 없고 퇴치로만 얻음 |
| 장착 | 캐릭터에 스킨 1, 액세서리 1, 펫 1 |
| 컬렉션 | 얻은 스킨, 펫, 퇴치 기록(몬스터 모습과 기간만. 병명·약 이름 없음) |
| 판매 | 없음. 뽑기권은 기록으로만 얻음 |

### 7.2 데이터

| 테이블 | 주요 칸 | 용도 |
|---|---|---|
| `collection` | 아이템, 등급, 얻은 날, 얻은 경로(뽑기/퇴치) | 컬렉션 |
| `tickets` | 뽑기권 수, 얻은 경로 | 뽑기권 |

`character`의 장착 칸을 씁니다. 스킨·액세서리 12종과 펫 그림은 에셋으로 앱에 넣습니다.

### 7.3 화면

| 화면 | 보여 주는 것 |
|---|---|
| 뽑기 (새로) | 뽑기권 수, 확률, 뽑기 결과. 연출은 5단계 |
| 컬렉션 (새로) | 스킨, 펫, 퇴치 기록, 장착 |
| 홈 | 장착한 스킨·액세서리·펫이 캐릭터에 보임 |

### 7.4 끝난 기준

- 7일 연속 기록과 퇴치로 뽑기권이 늘고, 뽑기권 없이는 뽑을 수 없음
- 뽑기 결과가 공개한 확률대로 나옴(테스트로 분포 확인), 얻은 것이 컬렉션에 남음
- 장착하면 홈 캐릭터에 반영되고, 퇴치 기록에 병명·약 이름이 없음

## 8. 5단계: 연출과 공유 카드

규칙이 자리 잡은 뒤에 보여 주는 쪽을 만듭니다.

| 항목 | 내용 |
|---|---|
| 보상 연출 | 저장 직후 몬스터 체력 감소, 경험치 막대 애니메이션 |
| 퇴치 연출 | 퇴치 애니메이션, 펫 획득, 뽑기권 획득 |
| 뽑기 연출 | 뽑기 애니메이션과 등급 공개 |
| 성장 연출 | 단계가 오를 때 캐릭터가 바뀌는 연출 |
| 공유 카드 | 장착한 캐릭터를 이미지로 저장(웹은 내려받기). 약 이름과 병명은 안 나옴. "저 스킨 어떻게 얻었지?"를 만드는 첫 단계 |

### 8.1 끝난 기준

- 저장, 퇴치, 뽑기, 성장에서 연출이 나오고 건너뛸 수 있음
- 공유 카드를 휴대폰 사진첩(웹은 파일)에 저장할 수 있고, 카드에 약 이름·병명·기록이 없음

## 9. 6단계: 테스트 배포와 4주 검증

### 9.1 배포 전 점검

| 항목 | 내용 |
|---|---|
| 나이 확인 | 처음 열 때 만 14세 이상인지 확인. 아니면 쓸 수 없음 |
| 모델 한계 안내 | 의약품 96종만 알아보고 영양제는 모른다는 점을 앱 안에 적음 |
| 놓친 약 안내 | 몬스터 상세와 놓친 날에 "의사·약사의 안내를 따르세요" |
| 병명·약 이름 노출 점검 | 몬스터, 펫, 컬렉션, 공유 카드에 병명·약 이름이 없는지 화면마다 확인 |
| 백업 | 새 테이블이 모두 엑셀 백업에 들어가는지 확인 |

### 9.2 성공 지표

10~20대 테스터 10명이 4주 동안 써 보고 아래 지표를 봅니다. 목표치는 첫 주 결과를 보고 정합니다.

| 지표 | 계산 | 보는 이유 |
|---|---|---|
| 기록한 날 비율 | 28일 중 기록한 날 | 기록을 이어 가는가 (핵심) |
| 일정 완료율 | 일정을 다 지킨 날 / 일정이 있던 날 | 하루치를 끝까지 먹는가 |
| 처방 완주율 | 퇴치한 몬스터 / 등록한 처방 | 처방을 중간에 끊지 않는가 |
| 사진 기록 비율 | 사진으로 한 기록 / 전체 기록 | 보상이 사진 기록을 끌어내는가 |
| 공유 카드 저장 수 | 사용자당 저장 횟수 | 보여 주고 싶은 보상인가 |

기록이 모두 기기 안에 있으므로 지표도 기기 안에서 셉니다. 테스터가 매주 엑셀 백업을 보내거나, 앱 안의 지표 화면을 캡처해 보냅니다(8장).

### 9.3 끝난 기준

- 테스터 10명이 웹 링크로 열어 4주를 씀
- 첫 주 결과로 목표치를 정하고, 4주 뒤 지표를 표로 정리함

기획서에서 정하지 않았거나 제안으로 남은 것입니다.
